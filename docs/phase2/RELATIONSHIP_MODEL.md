# Directional relationships

The original source→target record is authoritative. New v3 starts with sparse colleague links plus missing employee→manager links. New hires/moves/manager assignments reuse an existing edge or add the required direction; IDs enforce uniqueness. No all-to-all graph is generated. Relationships persist as historical context when people leave. Indexes are derived, never saved copies of scores.

V1/v2 weekly drift remains unchanged. V3 changes require successful ongoing collaboration (both active, same team and performance ≥45), pressured collaboration or direct manager support. Trust/affinity/respect/resentment changes are bounded. Crossings below trust 35 or above 80 produce causal events and bounded memories. A transfer changes collaboration eligibility and managerial context rather than adding arbitrary cross-team decay. Departure still affects surviving people through real incoming affinities.

Promotion updates employee→manager trust. Existing same-team incoming ambitious peers may respond to progression, trust and readiness; neutral reactions are silent. No salary comparison awareness, fabricated dialogue or new relationship subsystem is modeled.

Consequences: relevant managerial trust influences support; existing team ties influence coordination and retention. Strong ties reduce exit-target pressure by a bounded amount; they cannot negate all compensation/workload/career problems. CLI matched branches include full relationships for diagnosis, normal UI only qualitative summaries (up to six relevant existing contacts).

Graph processing is O(N+E). Repeated player reassignments can accumulate historical manager edges; there is no automatic quadratic expansion. A future history-pruning policy may be needed for extremely long games with many reorganizations, outside this phase's tested stress scenario.
